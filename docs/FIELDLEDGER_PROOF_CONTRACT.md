# FieldLedger Proof Contract

## 1. Purpose

This contract defines a future-planning boundary for ticket and receipt proof handling.

It does not change current MVP scope.

The current MVP remains worker-owned, offline-first, no-login, no-backend, net-zero-cost, and manual-review-first.

## 2. Proof By Reference

Ticket and receipt proof should be tracked by reference.

Proof references may include local photo IDs, file names, receipt IDs, ticket IDs, or later controlled links.

## 3. Payroll Row Boundary

Proof must not be stuffed into payroll rows.

Payroll or timesheet rows should keep structured values separate from proof files.

## 4. Future Proof Layout

Future workflows may use:

- a Proof tab
- a proof bundle
- controlled proof links
- proof reference columns

These are not required for the current MVP.

## 5. Local-First MVP Boundary

Current MVP proof remains local-first.

Local proof storage must not require backend storage, user login, paid cloud storage, OCR, or AI.

## 6. Controlled Sharing

Controlled proof sharing may be added later.

Future sharing must be explicit and worker-approved.

## 7. Privacy And Security

Proof may contain private location, payment, vendor, job, or personal information.

Future proof sharing must protect local records, backups, tokens, file links, and private notes.
