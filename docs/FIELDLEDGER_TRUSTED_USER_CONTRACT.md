# FieldLedger Trusted User Contract

## 1. Purpose

This contract defines the future-planning boundary for trusted-user testing.

It does not change current MVP scope.

The current MVP remains worker-owned, offline-first, no-login, no-backend, net-zero-cost, and manual-review-first.

## 2. Testing-Only Boundary

Trusted-user access is for limited testing only.

It is not a public release, launch, production rollout, or support promise.

## 3. Tester-Owned Copy

Each tester should use their own FieldLedger browser data and their own Google Sheet copy.

No tester should use the owner's master Sheet as their active test Sheet.

## 4. Local Browser Data

FieldLedger data is local to the browser and device used.

Phone, laptop, desktop, normal browsing, and private browsing data may be separate.

## 5. Transfer Method

JSON backup and JSON import are the transfer path between devices or browsers.

Trusted-user testing must not imply account sync, backend sync, or shared cloud storage.

## 6. Tax Boundary

FieldLedger tax estimates are planning only.

Trusted-user testing must not present tax estimates as tax advice, filing guidance, or guaranteed tax liability.

## 7. Public Release Boundary

Trusted-user testing does not mean FieldLedger is publicly released.

Tester feedback must not be treated as production acceptance.

## 8. Feedback To Collect

Trusted-user feedback should collect:

- device and browser used
- workflow tested
- sample totals expected
- sample totals observed
- export/import result
- Sheet result when applicable
- backup/restore result
- screenshots or notes for failures
- date tested

## 9. Evidence Rule

Evidence should be specific enough to reproduce issues.

Generic notes such as "worked" are not enough for trusted-user validation.
